# Sources

- The owner's answers of 2026-10-16: tech debt is caught at feature time,
  plus one weekly routine that reviews the week's changes and proposes
  redesigns, one card each; architecture never accumulates debt, since a new
  requirement is designed in as if it had been there from the start. The
  charter's "What I reject" lists the debt kinds: dead code, a second way to
  do the same thing, a workaround where a redesign was due, a feature bolted
  on instead of designed in.
- pstack (cursor/plugins@99743e9, MIT, Lauren Tan):
  `principle-redesign-from-first-principles`, `architect`'s design red flags
  and scrap tells, and `correct`'s "delete old ways an agent would copy".
- The cap of five cards a week and the no-card path for unreachable dead
  code are this skill's own, to keep the owner's attention for the
  redesigns; the charter lets agents decide what isn't on its card list.
